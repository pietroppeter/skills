nimib-theme: does each rule earn its place?

2026-11-08 · first devlog post

The nimib-theme skill exists because our nimib pages kept breaking on the phone: 20px code spilling out of its box in Declarative Dragging, no highlighting at all in Cartographer. Its rules were written while fixing those pages. This post checks them one by one on a small demo page, so you can decide which ones stay.

The experiment

demo.nim has a code block with a long line, its output, and a Nim fence in markdown. Its theme is the kind anyone writes by hand:

pre code { font: 13px/1.5 monospace; background: #f3efe6;
           border: 1px solid #d9d0bb; display: block; padding: 8px }

It is built three ways and screenshotted at 390px, with CDN stylesheets and cdn.jsdelivr.net/gh/ scripts blocked the way a claude.ai artifact blocks them. Each build also goes through phonecheck.js.

1. nimib 0.4.3 (before #267)

✗ old.html
    page is 548px wide at 390px
    20.4px code: let languages = @["nim", "python", "javascript", "
    17px code: nim, python, javascript, rust, zig, odin, c, cpp,
    pre does not scroll: nim, python, javascript, rust, zig, odin, c, cpp,
    20.4px code: proc greet(name: string): string = "hello, " & nam

The theme asks for 13px and gets 20.4px: nimib's own pre > code {font-size: 1.2em} comes after the theme in the page and is more specific than pre code. The output doesn't scroll, so the whole page becomes 548px wide and slides sideways. There are no colours: the highlight theme is a CDN stylesheet, and the artifact blocks it.

That is rule 1 (use nimib #267, or write body pre > code on older nimib) and the reason for rule 2.

2. nimib #267, without nb.inlineAssets

✗ new.html
    17px code: nim, python, javascript, rust, zig, odin, c, cpp,

#267 makes nimib's base rules lose to any theme rule, and makes every block scroll inside its box. The code is 13px and the page fits. Two things are still wrong. There are still no colours, because the highlight CSS still comes from a CDN: that is rule 2, call nb.inlineAssets. And the output is 17px, because outputs are pre.nb-output with no <code> inside, so the theme's pre code rule never reaches them: that is the pre.nb-output line of rule 3. phonecheck caught that; I would not have spotted it in the screenshot.

3. nimib #267 + nb.inlineAssets + one more theme rule

✓ good.html

The only change to the theme is pre.nb-output {font: 13px/1.5 monospace}.

Verdict, rule by rule

Rule Shown here? Keep?
1. nimib #267, else body pre > code yes, build 1 keep; shrink the fallback once #267 is released
2. nb.inlineAssets for artifacts yes, builds 1-2 keep
3. code 12.5-13px taste your call
3. overflow-x on a code box with a background only on old nimib fold into rule 1's fallback
3. style pre.nb-output too yes, build 2 keep
3. colour the hljs-* classes when replacing nimib's highlight CSS keep, it is one line
3. non-Nim code needs highlight.js not tested shorten or drop
4. phonecheck at 390px caught every problem above keep
5. publish as an artifact not about themes move to its own skill

phonecheck had one bug of its own: given a path that doesn't exist, it printed ✓. Fixed in the skill's copy of the script.

What I'd change

  • Split it in two. nimib-theme keeps rules 1, 3 and 4. A new nimib-publish skill takes rule 2 and rule 5: inline the assets, check, publish as an artifact, republish to the same link. Publishing is about your workflow, not about themes, and a page with nimib's default theme still needs it.
  • Trim rule 3 to the lines this demo proved, plus the size range.
  • Rewrite rule 1 once #267 is in a nimib release: "needs nimib ≥ 0.4.4" and a one-line fallback.
